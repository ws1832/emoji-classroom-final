# 学生网页摄像头接入与采样规范

修订日期：2026-11-13。

**产品方案：仅学生网页采集，AI 结果强制匿名，不保留公共摄像头入口。**
普通电脑的内置摄像头或 USB 摄像头即可作为输入；学生侧不安装 Python、
DeepFace、OpenCV、浏览器插件或本地采集程序。模型与依赖由管理员安装在独立 AI 服务主机上。

**实现状态：** 学生网页控件、短期采集会话/时间槽 API、独立单帧推理服务、
管理员配置、教师只读匿名计数、增量迁移与部署入口已实现。2026-11-13本机真实
`getUserMedia` → 单帧HTTP → edge真模型 → 匿名数据库记录 → 原看板短测通过：
3次采样，2条匿名入库，1次无脸；停止后全部track释放。没有保存原图/录像。
此项与早前Python USB节点测试分别记录，不将短测当作全班吞吐或课堂准确率验收。

## 1. 为什么只保留学生网页采集

实验指导书 §3.1 要求 AI 服务独立部署，通过 REST 或消息提交结果；
§6 要求视频帧采样、至少五类映射、可配置频率/阈值、匿名化、重试和错误日志。
**没有要求公共摄像头、专用采集设备或固定的每节课采样次数。**

网页获取摄像头、服务器上的独立 Python 服务负责推理，仍符合上述分层要求。
原学生 MANUAL 反馈、课堂排课、教师查询、管理端看板与 CSV 保留，不新建第二套门户或数据库。

旧 USB/RTSP 节点不再作为正式用户操作路径；既有代码/测试仅历史证据与回归工具，
未使用的旧节点UI已删除。实际自部署服务/模型/版本见 `AI_SERVICE.md`。

## 2. 谁采集、谁推理、结果保存什么

```text
学生电脑：原 Vue 学生课堂页面
  登录 → 选择已排课课堂 → 主动授权摄像头 → 本机预览 → 定时取单帧
                              │ 短期受限上传授权 / HTTPS
                              ▼
服务器：独立 Python AI 服务
  有界内存接收 → 人脸检测 → 单人检查 → 表情分类 → 置信度过滤
                              │ 独立服务凭证 / 原后端 API
                              ▼
原 FastAPI / 同一业务数据库
  课堂授权校验 → 事务 receipt / 幂等 → 匿名 EmojiRecord
                              ▼
原教师课堂 / 管理端看板 / 统计 / CSV
```

- 摄像头是学生当前电脑的摄像头，不是服务器上的摄像头。
- 学生登录用于排课授权、配额和防重复，不用于给表情记录填写姓名或学号。
- 所有 AI 业务记录 `user_id=None`；教师不能据表情结果界面查询学生的摄像头账号映射。
- 学生用户 `token` 只能申请/停止自己的采集会话，不能提交 AI 标签或置信度。
- 长期 AI 服务凭证只在服务器受限存储中存在，不进入浏览器、源码、URL 或页面持久化存储。
- 浏览器只拿到短期、单课堂/单采集会话、限定上传用途的授权。
- **网页路线需要上传采样帧供服务器推理。** “结果匿名、不保存原图”不等于“不传输原图”。
  原始帧只在浏览器和 AI 服务内存中短暂存在，不落业务库、临时文件、outbox、日志、trace 或录像。
- 只重试已生成的元数据事件；网络恢复后不补传课堂历史图片。

“结果匿名”不承诺整个鉴权系统完全不可关联；采集授权的临时控制信息必须有明确过期、
撤销和清理机制，与长期表情结果分开，不能把身份线索塞入 `device_source` 或 CSV。

## 3. 学生操作流程

入口沿用 `/student/classroom`，不新增独立设备配置页面：

1. 使用原学生账号登录，选择自己的已排课课堂。
2. 页面显示采集用途、匿名规则、课堂时间和本次采样间隔。
3. 点击「开启摄像头」，浏览器弹出权限提示；学生自己允许后才可获取画面。
4. 允许摄像头后自动显示本机预览并申请短期授权，从下一个时间槽开始采集。
   页面只显示状态、间隔、本页尝试次数/确认入库数和启停按钮，不另设“开始采集”按钮。
5. 保持单人入镜。无人脸、多人或低分时显示原因，不产生强行映射的记录。
6. 点击「停止摄像头」释放摄像头；需要恢复时重新点击「开启摄像头」并重新获得授权。
7. 点击「停止」、退出账号、切换账号/课堂、课堂结束或授权失效后释放全部摄像头 track，
   中止在途上传，并撤销采集会话。改密/管理员重置密码也撤销原JWT与采集授权。
   管理员开启课堂不能代替学生同意摄像头权限。

拒绝摄像头权限、没有摄像头或不想参加自动采集时，原 MANUAL 反馈照常可用。
不要求学生整节课持续授权，也不以未采集作为缺勤或评分依据。

生产网页与帧上传入口使用 HTTPS；本机开发走 `localhost`。
局域网部署不能把另一台电脑的 `localhost` 当作服务器地址，
也不能为了获取摄像头而要求学生安装证书绕过工具或关闭浏览器安全限制。
浏览器/系统权限、兼容性和设备选择必须作为真实验收项，不仅依赖模拟视频输入。

## 4. 教师和管理员的操作边界

### 教师

通过「我的课堂 → 课堂详情」或所授课堂实时看板，只读查看课堂采集状态、
采样间隔、匿名分布、有效观测数、无脸/多人/过滤计数。
没有服务身份/采集管理菜单，不设置阈值或间隔、不启停课堂采集、不查看原始视频。
跨教师课堂在后端拒绝，而不是只隐藏按钮。页面不提供网络异常独立计数。

### 管理员

负责一次性部署后端、Web、独立 AI 服务、模型准备、HTTPS入口和容量限制。
学生机器不安装模型；管理员使用的服务身份不是“每位学生一份永久设备 token”。
管理工作台面向全部课程和课堂，没有「我的课堂/我的教室」或学生反馈入口；
即使管理员历史上关联课程或排课，也不切换成教师/学生门户。
在「课堂采集管理」选择全局课堂，或从「课堂会话 → AI采集」、实时看板进入，
统一配置间隔/阈值、开启或停止课堂采集。高级参数折叠显示，不重复服务注册表单。
非超级用户的 ADMIN 角色同样可管理全局课堂，配置接口还检查动态路径 RBAC。

### 指导书依据与学生最小权限

指导书 §2.1–2.2 区分管理员管理用户/排课/数据与教师查看所授课堂数据；
§6 要求频率和阈值可配，但没有指定教师必须拥有采集启停权，
也没有要求学生必须开启摄像头。管理员统一控制是本项目符合这些要求的最小权限决策，
不是声称原文硬性规定。旧 CLI 任务管理也限管理员，防止教师绕过网页只读边界。

学生不改采样规则、不控制整个课堂、不选择模型、不持有 AI 服务凭证或提交 AI 标签。
仅在管理员启用的已排课课堂内，授权或停止自己的本机摄像头；
浏览器摄像头授权与释放属于本机设备操作，不能用管理员权限替代。
原手动 emoji、个人手动历史保留。

部署验收至少包括：

1. 后端健康检查、迁移和原 A/B/C 功能通过。
2. AI 服务模型校验及预热通过；缺模型不得 fallback 到假结果。
3. Web 入口和独立帧入口的 TLS、来源、短期授权验证通过。
4. request body/图片尺寸/格式/上传速率/并发限制在读取和推理前执行，
   网关、应用、错误日志均不保存请求图片或凭证。
5. 一台普通电脑实际授权摄像头，单帧 → 真模型 → 服务认证 API → 匿名记录 → 原看板通过。
6. 两个学生及多标签页隔离、停止释放、课堂结束与网络故障通过。
7. 测过对应班级规模后，才将采样配置投入课堂；不能把单人测试当成全班吞吐证明。

服务配置和凭证写入本地忽略目录或部署 secret store；正式文档、源代码和测试提交 Git，
权重、原图、运行配置和私人规划不提交。

## 5. 一节课采样多少次

实验没有固定次数。采用按时间调度，而不是“每节课必须凑够多少条记录”。
**已实现的默认间隔：10 秒；管理员可选择 5、10、15、30 秒。**

网页从下一个相位时间槽取样、课堂采用半开时间窗 `[start,end)`；
完整45/90分钟时间预算如下，实际开放时刻/漏槽会减少次数：

```text
单端采样次数 = ceil(采集持续秒数 / 采样间隔秒数)
平均请求速率 = 同时采集端数 / 采样间隔秒数
```

| 间隔 | 45 分钟 / 每端 | 90 分钟 / 每端 | 50 端平均输入 |
| --- | ---: | ---: | ---: |
| 5 秒 | 540 次 | 1080 次 | 10 帧/秒 |
| **10 秒** | **270 次** | **540 次** | **5 帧/秒** |
| 15 秒 | 180 次 | 360 次 | 约 3.33 帧/秒 |
| 30 秒 | 90 次 | 180 次 | 约 1.67 帧/秒 |

例如 50 端、45 分钟、10 秒间隔，理论最多 13500 次采样请求。
这些是时间预算，**不是已经实测的服务器吞吐、准确率或有效记录数**。
学生晚加入、暂停、掉线、页面后台、多人入镜、无脸或低置信度均会减少有效记录。

10 秒是兼顾趋势粒度与负载的工程起点，不是经课堂标注研究证明的最佳间隔。
2 秒留作短期模型/链路调试，不作为全班默认。正式班级应比较 5/10/15/30 秒下的
可见趋势、拒识率、排队与延迟，再决定配置；不能只依据单张图片的推理耗时估算容量。

### 调度规则

- 摄像头预览刷新率和 AI 采样率分开；预览连续并不意味着每帧上传或录像。
- 使用课堂时间槽以及分散的端点相位，避免全班同时开始导致同一秒集中上传。
- 每端最多一个在途请求；繁忙或错过时间槽直接跳过，不累计任务补发。
- 服务端限制同一采集端每时间槽最多一条有效观测；更换标签页/重启不能重置配额。
- 页面进入后台立即停止并释放摄像头；回到前台后由学生重新开启，不自动恢复，不补传旧帧。
- 课堂结束、管理员停止、学生停止自己的摄像头或授权失效后不产生新观测；
  浏览器元数据队列TTL为60秒，且最终入库仍要求采集授权有效；
  停止/课堂结束/撤销后未入库的结果也会拒绝。旧节点15分钟补交规则不适用于网页路线。

## 6. 如何避免重复

匿名模式不做人脸识别，也不保存身份 embedding。防重复分成三种不同问题：

| 问题 | 处理要求 |
| --- | --- |
| 同一学生多标签页/多设备启动 | 后端唯一活动采集会话；超时/撤销可释放，不只靠浏览器锁 |
| 重复点击、网络响应丢失、重传 | 稳定 frame/event UUID、服务端领取与事务 receipt；同事件只有一次业务效果 |
| 一个人被多台不同账号摄像头拍到 | 单人入镜规则减少风险；匿名且无身份识别时不能保证跨摄像头绝对去重 |

单人检查必须发生在“挑选通过表情阈值的观测”之前：
检测到两张脸即跳过整帧，不能因另一张脸太小或表情低分而把帧当成单人。
在检测范围内没有脸时也跳过，不能写成 `NEUTRAL`。
检测漏掉背景脸的可能性应在验收中记录，单人门不等于人员身份核验。

同一个人在不同时间槽产生不同观测，是时间序列采样，不是网络重复数据。
看板显示“AI 观测条数”，不能用其替代唯一学生人数。
多人之间的采样时长不同也会影响分布；没有身份归属的匿名结果不能假装做了逐学生等权统计。

## 7. 验收与故障清单

| 情况 | 期望结果 |
| --- | --- |
| 普通电脑内置/USB摄像头 | 网页授权、预览、真实单帧推理、匿名入库通过 |
| 权限拒绝 / 无摄像头 / 摄像头被占用 | 中文提示，不启动假采集；MANUAL可用 |
| 无人脸 | 无脸计数增加，AI记录不增加 |
| 多人入镜 | 多人计数增加，整帧不入库 |
| 低分 / unsupported emotion | 过滤计数增加，不强行改成五类之一 |
| 多标签页 / 重复请求 | 一个活动会话，同一事件只有一次记录 |
| 未排课 / 其他课堂 / 用户JWT写AI | 服务端拒绝，不以隐藏按钮代替权限验证 |
| 过期 / 撤销 / 课堂结束 / 登出 | 停止 track、上传和新入库 |
| 断网 / 服务繁忙 | 有界等待、丢弃错过帧，不缓存或补传原始图像 |
| 原看板 / 统计 / CSV / 学生历史 | 原契约保留，AI仍匿名，不混入学生个人历史 |

## 8. 管理员首次接入：Windows普通电脑/独立服务器

### 8.1 准备原项目和模型

学生无需安装以下内容。管理员先按根README启动原后端和前端，
在独立 `ai-service/.venv` 安装选定profile并按 `ai-service/README.md` 下载、校验模型。
推荐先用已实测的CPU `edge`；`standard`可选DeepFace emotion-only，不同时开两套服务争抢同一身份。

升级已有库前先备份；只使用单一迁移入口，API多副本不要并发迁移：

```powershell
.\.venv\Scripts\python.exe scripts/backup_sqlite.py --source db.sqlite3 --destination .local/backups/before-browser.sqlite3
.\.venv\Scripts\python.exe scripts/migrate.py
```

MySQL使用对应备份方式再运行同一迁移入口。迁移3仅新增 `ai_job.input_kind`
和短期 `ai_browser_capture/frame/budget` 表，不重建课程/课堂/MANUAL记录。
`database/ai_browser_*.sql` 是结构参考，不要在Aerich升级后重复手动执行ALTER。

### 8.2 注册的是服务器服务身份，不是学生摄像头

1. 管理员进入「课堂情绪管理 → AI服务身份」。
2. 填服务名，例如「学生网页AI服务」；来源别名填 `student-browser`。
   别名会出现在AI记录/CSV中，禁止填学生姓名、学号、账号、摄像头URL或密码。
3. 点击注册，记下服务ID。学生采集权限来自原课堂排课，教师读取权限来自课程归属。
   页面不要求填写教师授权ID，也不为每位学生注册设备；旧接口字段仅兼容历史回归。
4. 点击「签发/轮换凭证」，将一次性凭证保存到服务器受限文件
   `.local/browser-ai/service-token`，只保存凭证文本，不含引号。关闭弹窗后明文不可重读。
   不放Git、不放前端env、不放命令参数，不需要为每个学生发长期凭证。
   签发/申请响应是真正HTTP `Cache-Control: no-store`，审计只保留操作元数据。
5. 在后端本地 `.env` 设置并重启后端：

```dotenv
AI_BROWSER_DEVICE_ID=填注册得到的服务ID
AI_BROWSER_UPLOAD_URL=/ai-stream/frames
```

### 8.3 启动独立AI服务

从仓库根目录执行：

```powershell
New-Item -ItemType Directory -Force .local/browser-ai
Copy-Item ai-service/browser.example.json .local/browser-ai/config.json
.\ai-service\.venv\Scripts\python.exe -m emoji_ai.cli doctor --profile edge --manifest ai-service/models/manifest.json --model-dir ai-service/models --detection-threshold 0.85
.\ai-service\.venv\Scripts\python.exe -m emoji_ai.browser_service --config .local/browser-ai/config.json
```

修改复制出的JSON：`token_file`对应受限凭证文件；`backend_url`是原后端
`/api/v1`；`manifest/model_dir`对应已验证权重；`outbox_path`为忽略目录；
`allowed_origins`精确匹配学生网页来源（包括协议和端口），禁止 `*`。
`capacity=4`只表示最多4个已获准上传/等待处理请求，不是4个并行模型或已支持全班。
当前模型单线程串行、帧等待队列最多1个、HTTP连接线程最多16个；繁忙返回503，不无限排队。
多课堂共用同一服务身份，各课堂租约单独校验。不得同时启动旧CLI Worker抢此身份。

开发端口：原API9999，AI9998，Web3100。Vite将
`/ai-stream/frames`代理到本机AI服务；首次修改Vite配置后须重启前端dev进程。
本机浏览器只需访问 `http://localhost:3100`，无需填写摄像头index。

检查：原API `/healthz`返回ready；AI `http://127.0.0.1:9998/healthz`
返回 `ready:true`。AI认证失败会停止工作，不降级到假结果。
同一服务身份重启后可能等待旧45秒租约过期才恢复ready；
期间显示degraded/heartbeat_unavailable，不是直接绕过旧服务代际。
服务在线后，管理员选择当前课堂点击「开启课堂采集」，学生才会出现可用开启按钮。
同一电脑既部署服务又作为学生终端是允许的，但仍通过网页摄像头和独立服务鉴权分层，
不是让Python与浏览器同时打开同一摄像头。

### 8.4 局域网/互联网部署

生产为学生提供可信HTTPS网页及同源 `/ai-stream/frames` 入口，
AI监听内部端口，不把9998直接作为公开无网关服务。
学生机器上的 `localhost` 是学生自己，不是学校服务器。
反向代理已提供关闭图片请求缓冲/访问日志、256KiB限制的配置；
外层TLS网关也必须关闭请求体录制、缓存、trace和错误body输出。

Docker额外配置：

```powershell
$env:AI_BROWSER_DEVICE_ID = '填服务ID'
docker compose -f deploy/compose.yml -f deploy/compose.browser.yml up -d --build
```

先在基础API注册身份，将受限文件放到
`.local/deploy/ai_service_token`；复制 `deploy/browser.linux.example.json`
到 `.local/deploy/browser.json`，修改为实际HTTPS后端地址和来源；
API的 `CORS_ORIGINS` 同时修改为实际网页来源，不能保留示例localhost。
模型挂载 `/models`，匿名元数据队列挂载 `/outbox`；容器不映射USB设备。
容器构建/HTTPS网关和目标Linux环境仍需实际验收，不能依据模板声称已通过一键部署。

## 9. API与资源生命周期

| 接口 | 身份 | 用途 |
| --- | --- | --- |
| `GET /api/v1/ai/browser/classrooms/{id}` | 已排课STUDENT | 当前课堂采集配置 |
| `GET /api/v1/ai/browser/manage/{id}` | 所属TEACHER/ADMIN | 只读状态、revision、匿名汇总、`can_configure` |
| `PUT /api/v1/ai/browser/manage/{id}` | ADMIN + RBAC | 统一配置/启停课堂采集，教师与学生均403 |
| `POST .../classrooms/{id}/captures` | 学生，`consent:true` | 一次性内存上传token |
| `POST .../captures/{uuid}/renew/stop` | 原学生身份 | 20秒续期/停止自己的60秒授权 |
| `POST /ai-stream/frames` | 短期bcc授权 | `image/jpeg`二进制单帧，`X-Frame-ID` UUIDv4 |
| `POST .../worker/claim/outcomes` | 长期aic服务身份 | 领取时槽票据、单人/过滤结果 |
| `POST /api/v1/ai/emoji-results` | 长期aic服务身份 | 复用严格v1匿名元数据入库 |

浏览器不提交emoji/confidence/student_id；业务API不接收图片；
服务收到帧先验证授权/服务代际/课堂/时槽再解码，JPEG头尺寸最大1280×720，
拒绝多SOF/不支持JPEG头并忽略EXIF自动旋转，保持先验尺寸与native解码一致；
网页编码最多640×480、JPEG质量0.75，不采集音频、不录像。
原始图片读取5秒超时，单次网页请求20秒超时，错过时槽丢弃。
停止即清除采集表的owner/token/活动键，过期同样清除；15分钟后分批删除票据。
HMAC配额键不公开、无用户外键，保留到课堂结束后15分钟以防反复重开重置配额。
AI服务每5秒心跳触发清理；服务停机时到期授权不能使用，
残留控制数据将在服务恢复后清理，不是承诺数据库物理删除恰好发生在到期瞬间。
